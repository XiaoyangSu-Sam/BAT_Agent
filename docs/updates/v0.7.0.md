# Update to BAT Agent v0.7.0

Baseline: v0.6.1. This is a coordinated source update. Import the runtime files together so the page, API and database behavior match. Python and frontend dependency requirements are unchanged. No new virtual environment, dependency synchronization, Playwright installation or browser download is part of this update.

## What changed

- Chat occupies the main area. The left sidebar lists and searches conversations. Files open in an optional right coding pane, with resize, expand, split and close controls. Closing the pane retains unsaved drafts in memory; reloading the page does not.
- Execution approval offers Approve once, Decline, and Allow all for this conversation. Allow all persists across tasks and restarts. Require approval again restores the project policy for subsequent execution. Other conversations and write approvals under the all policy are unaffected.
- Blank YAML API keys are accepted. Exact request URL preserves a custom endpoint path. If the destination already has these connection fixes, merge them and preserve the working local connection settings.
- English development guidance, README rules and this selective-update workflow are versioned with the source.

## Before importing

1. Inspect the destination repository and current branch. Make a checkpoint commit for eligible source changes on that branch after reviewing the staged diff; preserve unrelated work and exclude credentials/local data. Record the commit ID. A source commit does not back up ignored files or provide an off-machine backup by itself.
2. Stop the destination app normally. Back up its local config, workspace, private Skills and entire .harness directory to an approved private location. Include the stopped SQLite database and any WAL/SHM sidecars. Record paths without printing secrets.
3. Keep the existing interpreter, .venv, Git metadata/remotes/hooks, organization instructions, local config and data in place. Do not replace .github or AGENTS.md with upstream defaults. Respect access restrictions and report any instruction file that cannot be reviewed.

## State migration, validation and rollback

Startup adds allow_all_execution to older session databases with a default of 0. Existing messages and conversations remain, and no existing conversation becomes auto-approved. The new code inserts sessions by column name. The old version inserts positional values, so a code-only downgrade after this migration is not supported: restore the stopped pre-update state backup together with the old source. Preserve a separate copy of newer state if it contains work you need; restoring the old backup loses later conversation changes.

Use the existing interpreter from the project root:

```powershell
$BatPython = Read-Host "Full path to the existing approved python.exe"
& $BatPython scripts/check_environment.py
```

If it reports ok: true, run available tests with the same interpreter, then start `& $BatPython -m agent_harness`. Do not install packages or recreate the environment simply to make the test command available. Report missing test tooling separately from a runtime failure. Reload the browser after restart.

Check these behaviors using disposable workspace files:

- Chat is the default large pane. Conversations can be created, selected and searched.
- Files open on the right; close, resize, expand and split work. Closing/reopening keeps an unsaved draft. Saving still detects an external file conflict.
- A Python execution requests approval. Approve once permits that operation only. Allow all permits later execution in that conversation, including after reload/restart. A different conversation still asks. Require approval again makes the next execution ask. Under the all policy, file writes still ask.
- The existing connection, registered Skills and workspace files still load. Test a model connection only against the already approved destination and configuration.

Local release checks use a mock HTTP model, real temporary file writes and Python subprocesses. They are not a validation of your private model service or desk-booking site.

SOURCE-MANIFEST.json describes upstream bytes. If files are merged with local customizations, do not claim an exact upstream match. Review those differences and regenerate a destination manifest through its established process. A matching hash does not replace functional validation.
